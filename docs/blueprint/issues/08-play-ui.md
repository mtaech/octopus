# 游玩界面设计

Type: prototype
Status: resolved
Assignee: agent
Blocked by: 03

## Question

设计游玩界面的信息架构与演出方式。需要回答：对话/叙事如何演出（聊天流 vs 剧本式）；角色面板/地图/任务日志/骰子判定如何布局；流式输出与等待结算的交互节奏如何呈现。产出一个可交互的粗糙原型，原型作为资产链接在本票上。
## Assets

- 可交互原型（三变体对比 A 聊天流 / B 剧本式 / C 沉浸式视觉小说）：[prototypes/play-ui.html](../prototypes/play-ui.html)（单文件，浏览器直接打开；底栏或 ←→ 键切换变体；URL 参数 ?variant=A|B|C 可直达；顶栏「决议」抽屉内含本次 Q1–Q6 决议与演示脚本）

## Answer

**决议（原型 play-ui.html 三变体对比 + Q1–Q6 拍板）：**

**① 叙事演出形态 = 多模板**（用户反馈修订）：三套<b>演出模板</b>并存、玩家/创作者可随时切换（默认聊天流）——**A 聊天流**（IM 气泡，最贴「故事对话模拟」）/ **B 剧本式**（纸面浅色、说话人=角色的 script 排版，适合强节奏/场景切割）/ **C 沉浸式**（场景背景 + 底部文本框逐行演出，适合沉浸向）。同一场戏、同一回合模型与事件流，仅呈现层不同；模板切换是产品功能（游玩界面顶栏 🎭 选择器 / 底栏 ←→，?variant= 可直达）。

**② 布局 = 单栏叙事 + 抽屉。** 叙事是主舞台；面板形态各变体不同：A 居中聊天列 + 右侧演员卡，地图/日志为右抽屉；B 左侧角色表 + 剧本旁批注；C 顶部 HUD + 底部文本框 + 悬浮演员卡。判定结果 = **流内结算卡**（各变体自有形态），非模态弹窗。

**③ 确认门 = 流内挂起卡片**：拟执行动作 + 预估后果 + [确认][取消]，确认后原位变结算结果；顶栏「免确认」全局开关（开启后判定直接结算、不弹卡）。

**④ 元指令 = 同一输入框 / 前缀 + 常驻快捷按钮**（切换角色 / 存档 / 重来）；/切换 走角色选择面板，NPC 标注「仅剧情节点响应」、非控制角色由角色 AI 扮演。

**⑤ 演员卡 = 常驻紧凑**（关键属性/资源条/技能 chips，点开全表）；NPC 在场时轻量出现。

**⑥ 流式 = 就地打字机 + 点击/空格跳过 + 管线阶段徽标**（主线思考中→角色回应中→结算中）；判定卡呈现跟随故事书声明的判定器（演示故事书为 d20 风格参数），成功度按差值分档（显示名归演出模板映射）。

**待办交圈**：游玩界面与引擎之间的 **SSE 事件协议**（场景/旁白/对话/判定/待确认/系统事件 schema + 确认门往返 + 状态同步）成为新票；前端模块划分随事件协议落定。

**模板自定义（反馈修订）**：模板可自定义——CSS token 换肤 + 插件 API 双轨（详见 [演出模板的自定义与扩展机制](./19-template-customization.md)，Blocked by 08/17）。
