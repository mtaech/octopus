# 引擎职责边界（Rust / Lua / AI）

Type: grilling
Status: resolved
Assignee: agent
Blocked by: 01, 12

## Question

划分引擎的职责边界：哪些逻辑落在 Rust 引擎（状态、规则、结算、物品/技能框架），哪些落在 Lua 脚本（技能/判定/事件的动态计算），哪些由 AI 决定（叙事、角色言行）。需要拍板：
① 引擎暴露给 Lua 的 API 面（只读状态 vs 可写状态，如何防破坏）。
② Lua 的执行时机（结算钩子、事件触发、判定）。
③ 沙箱与热加载策略。
④ 判定规则（骰子/技能检定）是硬编码还是脚本化。
⑤ 确定性与随机种子策略。
参考「Rust 的 Lua 集成生态调研」的结论。
## Answer

### ① 三界划分

| 层 | 负责 | 不负责 |
|---|---|---|
| **Rust 引擎** | 状态权威、命令日志、结算管线（校验→扣资源→写状态）、随机数（RNG）、物品/技能框架、Lua 宿主 | 叙事、角色性格、世界逻辑 |
| **Lua 脚本** | 技能/物品的动态效果计算、事件触发条件、判定修正、自定义 UI 数据计算 | 直接读写引擎状态（只能通过引擎暴露的 API） |
| **AI** | 叙事走向、角色言行、是否使用技能/物品、元指令（切角色、开菜单） | 直接改状态、数值结算 |

### ② 引擎暴露给 Lua 的 API 面

**只读 API**（白名单注入 scoped env）：
- 当前角色实例的属性值、资源余额、当前状态（buff/debuff 列表）
- 当前场景 ID、当前回合数
- 技能/物品的声明式定义（读自己的 effect 配置）
- 关系图中与当前角色相关的边

**读范围严格限制**：当前角色 + 当前目标，不给 Lua 看到其他角色。

**可写 API**（请求-校验-执行模式，引擎永远是权威）：
- 发起一次判定（请求引擎产生随机值→Lua 拿结果）
- 声明资源消耗（引擎扣减框架约束）
- 施加/移除状态（引擎校验目标合法性、叠加规则）
- 触发事件（引擎广播给其他监听者）
- 查询世界（返回过滤后的实体列表）

**Lua 临时存储**：每个脚本有 per-script 的沙箱存储区（`_G` 子表），技能可跨回合记状态。

### ③ Lua 执行时机

| 时机 | 触发者 | 例子 |
|---|---|---|
| 结算前钩子 | 意图校验后、状态写入前 | "火焰护盾"在受伤前判定反伤 |
| 结算后钩子 | 状态写入后 | "生命药水"使用后播放恢复动画数据 |
| 事件触发 | 引擎广播事件 | "角色死亡"→清理持续效果 |
| 判定修正（随机前） | 引擎产生随机值前 | "精准射击"注入修正值 |
| 判定修正（随机后） | 引擎产生随机值后 | 某些技能改变成功度 |
| 条件评估 | beat/goal 评估 | 检查"是否击败 Boss" |

**钩子链规则**：按注册顺序执行；中间一个脚本报错，后续钩子不跑（fail-fast，防状态不一致）。

### ④ 判定规则：混合模式

判定器有两种来源：参数化配置（见 #12）或 Lua 判定脚本。作用域双轨：`world.rules.check` 全局声明；`skill.check` 可让单个技能引用或覆盖全局判定器。Lua 判定脚本受**归一化契约**约束——只返回最终值 `total` 与差值 `margin`，成功度档位仍由引擎按 `degree_thresholds` 分档（`level` 枚举稳定，对齐 #17），不能直接返回自定义档位；差值供叙事解读。引擎暴露 `roll_dice(dice_expr)`、`get_attribute(character, attr)` 与 `engine_rng(min, max)` 原语给 Lua 判定脚本（RNG 走确定性序列）。

### ⑤ 随机种子：可控 RNG

RNG 归引擎独家——Lua 不能调 `math.random`（`MATH` 库从白名单拿掉）。引擎暴露 `engine_rng(min, max)` 给 Lua，内部走命令日志的确定性 RNG 序列，保证可回放。
