# 账户与登录（多账户）

> 术语：**账户**是系统侧的登录身份，与领域里的**玩家**（操作者实体，控制角色实例）不是一回事——
> 一个账户对应现实中的人，一个玩家是故事里的角色归属。见 [CONTEXT.md](../CONTEXT.md) 的「账户」「玩家」。

本文件是账户 / 登录 / 资源归属的权威说明。实现落点：
`migration/src/m20260920_000021_create_accounts.rs`（表）、`crates/octopus-engine/src/accounts.rs`（持久化与密码学原语）、
`crates/octopus-api/src/auth.rs`（端点与守卫）、`frontend/src/lib/auth.ts`（前端登录态）、
`frontend/src/pages/auth/AuthPage.vue`（登录 / 注册页）。

## 1. 为什么会有这份文档

设计阶段的锁定决议是「只绑 `127.0.0.1`、无鉴权」（[决策记录 §12](./blueprint/decision-log-design-pass.md)、[#24](./blueprint/issues/24-play-backend-api.md)）。
多账户登录/注册是对这条边界的**有意变更**：让同一份实例可以有多个人各有各的存档与故事书，
并为将来「多人」预留身份层（#06 的 Player 实体是领域侧的另一半，两者不互相替代）。

变更后的边界：

- `/api` 除健康检查与 `/api/auth/{login,register}` 外，**一律要求登录**（fail-closed：新端点默认落在受保护集合里）；
- 资源按账户隔离（存档严格私有，故事书「作者的草稿私有 / 已发布共享」）；
- 若把 `OCTOPUS_ADDR` 绑到 `0.0.0.0`（局域网 / 公网），**必须**前置 TLS 反代
  （仓库里已有 `scripts/caddy-octopus.conf` 可参考）：口令与令牌不适合明文过网。

## 2. 数据模型

### users（账户）

| 列 | 说明 |
| --- | --- |
| `id` | 主键。默认管理员是固定常量 `user-octopus`，其余为 `user-<uuid>` |
| `username` | 唯一。**落库前一律规范化成小写**（去首尾空白 + `to_lowercase`），所以唯一约束天然大小写不敏感；允许中文 |
| `display_name` | 界面显示名，缺省回落用户名 |
| `password_hash` | **argon2id PHC 串**（含随机盐与参数）。任何响应 / 日志都不出现它 |
| `is_admin` | 管理员：唯一特权是读写全局配置（API Key / 全局模型） |
| `must_change_password` | 仍在使用初始口令。默认管理员初始为 true，改密后清除 |
| `created_at` / `updated_at` / `last_login_at` | 时间戳（RFC3339） |

### sessions（登录态）

| 列 | 说明 |
| --- | --- |
| `token_hash` | 主键 = 令牌的 **sha256 十六进制**。原始令牌只在签发那一刻的响应里存在，库被读走也拿不到可用令牌 |
| `user_id` | 归属账户 |
| `created_at` / `expires_at` / `last_seen_at` | 有效期 30 天；`last_seen_at` 最多每 5 分钟推进一次（避免每个请求都写库） |
| `user_agent` | 可选，便于日后做「登录设备列表」 |

过期登录态在**登录时**顺手清理（`purge_expired_sessions`），不需要额外定时任务。

### 归属列

`saves.owner_id` 与 `storybooks.owner_id`（可空，均带索引）。可空是迁移期的过渡态：
迁移只加列，**回填由引擎启动时的 `ensure_default_admin` 完成**（`WHERE owner_id IS NULL` → 默认管理员），
这样常量 `DEFAULT_ADMIN_USER_ID` 只在引擎里有一份，迁移器不必反向依赖引擎。

## 3. 归属语义

| 资源 | 读 | 写（改 / 删 / 发布） |
| --- | --- | --- |
| 存档 | 仅所有者。**列表按 `owner_id` 过滤；按 id 访问非自己的存档一律 404** | 仅所有者 |
| 故事书（未发布草稿） | 仅作者（404，不是 403） | 仅作者 |
| 故事书（已发布） | **所有账户**（跨账户的公共可开档库：可读 / 可导出 / 可试玩 / 可开档） | 仅作者 |
| 结对线程 | 仅其故事书作者 | 仅其故事书作者 |
| 全局配置 `/api/config` | **仅管理员** | 仅管理员 |
| 资产 `/api/assets/*` | 任何登录账户（内容寻址，天然去重共享） | 任何登录账户（上传） |

两条刻意的设计选择：

1. **越权回 403 还是 404？** 资源归属一律 **404**。用 403 区分「存在但不是你的」，
   状态码本身就变成 id 探测器。管理员权限（`/api/config`）才回 403——那不是资源归属问题。
2. **令牌无效 / 缺失回 401**，前端据此统一清登录态并回登录页。

「已发布 = 可被他人开档」不是新加的概念，它本来就是 `publish`（发布）在教育义上的用途：
发布前的草稿是作者的私产，发布后进入公共书架。删掉一本已发布的书不影响别人已开的档
（存档内嵌冻结副本，自包含）。

## 4. 令牌与传输

- 请求头：`Authorization: Bearer <token>`。
- **`?token=` 逃生口**：浏览器里有两类请求带不了自定义头——`EventSource`（演出流 SSE）
  与 `<img src>`（立绘 / 封面）。它们改用查询串传令牌，服务端**只对 GET** 接受这种形式
  （POST/PATCH 不接受，避免生成可分享的写操作链接）。
  请求日志只记 `uri.path()`，**不记查询串**（见 `logging::http_span`）。
- 前端存放：默认 **sessionStorage**（每标签页一份 → 同一个浏览器可以同时登两个账号，这才是「多账户」）；
  勾「记住我」才落 localStorage。读取时 session 优先。
- 登出只吊销当前会话；改口令会吊销该账户的其它所有会话（只留当前这条）。
- 登录失败限流：同一用户名 15 分钟内 10 次失败后 429（内存态，单进程本地服务够用）。
  登录失败与「用户不存在」返回**同一句话**，且未知用户也走一次等代价的口令校验，避免用响应时间枚举账号。

## 5. 默认管理员与历史数据

首次运行（`users` 为空）时自动创建：

- 用户名 **`octopus`**，口令 **`octopus`**，`is_admin = true`，`must_change_password = true`；
- **多账户之前的所有存档与故事书（含种子故事书）回填到它名下**；
- 启动日志打一条 WARN 提醒改密；前端在账户菜单上挂常驻警示点 + 登录后 toast，
  直到口令改掉为止。

之所以给可预测的初始口令：这是本机单人部署的引导账号，随机口令会把「第一次怎么进去」变成运维问题。
因此 `must_change_password` 的提醒不是装饰——绑定到局域网/公网前必须先改掉它。

## 6. 端点

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/register` | 注册并**直接签发**登录态（201） |
| POST | `/api/auth/login` | 登录（200，失败 401，限流 429） |
| POST | `/api/auth/logout` | 吊销当前会话（204） |
| GET | `/api/auth/me` | 当前账户（前端启动时校验本地令牌） |
| POST | `/api/auth/password` | 改口令（校验旧口令；吊销其它会话） |
| GET | `/api/health` | 公开：存活探针 |

校验规则：用户名 2–24 字符、不含空白 / 斜杠 / 控制字符（大小写不敏感，允许中文）；
口令至少 4 字符。前端 `AuthPage` 做同源校验只是为了少一次往返，**权威校验在后端**。

## 7. 路由守卫的装配方式

`octopus-api::router` 把路由分成两个集合再合并：

- `public`：健康检查 + 登录 / 注册；
- `protected`：其余全部 → 合并后统一 `route_layer(require_auth)`。

归属检查再叠一层 `route_layer`：`guard_save_owner`（按路径里的 `{id}`）、
`guard_storybook_read` / `guard_storybook_edit`、`guard_pair_thread_edit`、`guard_admin`。
**新增端点只要注册进 `protected` 就自动要求登录**；需要归属的端点放进对应的子路由即可，
不需要（也不应该）在每个 handler 里手写权限判断——那是漏检的来源。
取值失败（守卫漏配）返回 500 并在日志里报错，绝不当作匿名放行。

请求体里带 `thread_id` 的端点（结对对话，路径上没有 id）走 `ensure_pair_thread_owner` 显式校验。

## 8. 管理后台

界面在 `/admin`（`frontend/src/pages/admin/`），接口在 `/api/admin/*`（`crates/octopus-api/src/admin.rs`）。

**三层门禁**，缺一不可：

1. 路由 `meta.admin` + 全局守卫：非管理员直接被弹回列表页（连停留页都不给），并 toast 说明；
2. 账户菜单里的「管理后台」入口只对管理员渲染；
3. 服务端 `/api/admin/*` 是**一整棵子树**，集体挂在 `guard_admin` 之后 —— 新增管理端点只要挂进
   这棵子树就自动只有管理员可达。前两层只是「不给入口」，判决永远在服务端。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/overview` | 账户 / 管理员 / 存档 / 故事书 / 有效登录态 + 库文件路径与体积 + 版本 |
| GET | `/api/admin/users` | 账户列表（含每人内容统计、有效登录态数、`is_self`） |
| POST | `/api/admin/users` | 新建账户（管理员直接设定用户名 / 初始口令 / 是否管理员） |
| PATCH | `/api/admin/users/{id}` | 改显示名、提权 / 降权（省略字段 = 不改；空串 = 回落为用户名） |
| POST | `/api/admin/users/{id}/password` | 重置口令，并**吊销该账户全部登录态** |
| DELETE | `/api/admin/users/{id}/sessions` | 退出其所有设备（不改口令） |
| DELETE | `/api/admin/users/{id}` | 删除账户；`?purge=true` 才连带删除其存档与故事书 |

三条兜底规则（本地实例没有「找回管理员」的通道，必须由规则兜住）：

- **不能删除自己**（409 `cannot_delete_self`）——避免手滑把自己锁在外面；
- **不能删除 / 降级最后一个管理员**（409 `last_admin`）——否则这台实例再没人能进后台；
- **删账户默认拒绝**：账户还有内容时返回 409 `user_has_data` 并带上
  `{saves, storybooks}` 计数；必须显式 `?purge=true`（前端是勾选「一并删除」）才连带清理。
  「删账户」与「删数据」是两个独立的决定。

删除内容走的是用户侧同一条删除路径（`delete_save` + `drop_session`、`delete_storybook`），
所以命令日志、快照、归档、结对会话与内存会话 / 模型会话都会被正确清理，不留孤儿。

## 9. 已知取舍（不在 v1 范围内）

- **无 HTTPS**：本机绑 `127.0.0.1` 时可接受；对外必须由反代终结 TLS。
- **无找回口令 / 邮箱验证 / 二次验证**：本机部署下没有可信的第二信道；
  管理员可以重置别人的口令（见 §8），自己忘了只能直接改库
  （`UPDATE users SET password_hash=...`，或删掉该行重开）。
- **无角色体系**：只有「管理员 / 普通账户」两档。管理员的特权是全局配置读写 + 管理后台；
  它**不会**让你看到别人的存档（隔离对管理员一样成立，想看只能删——这是刻意的）。
- **管理操作没有单独审计表**：目前只写 `tracing` 日志（新建 / 提权 / 重置 / 删除都带
  `admin=<谁>` 与目标账户）。要做「谁在什么时候动了谁」的持久审计，得再加一张表。
- **限流是单进程内存态**：多实例部署不共享计数。
- **资产按登录共享**：不按账户隔离（内容寻址 + 去重是资产库的价值所在）；
  知道哈希即可读，属于本机部署可接受的取舍。
