# 核心游戏循环

Type: grilling
Status: resolved

## Question

定义单回合的核心循环与玩家交互模型。需要拍板：
① 单回合流程：玩家输入 → 主线 AI → 角色 AI → 引擎结算 → 输出，还是其他顺序/并行。
② 玩家输入的分层：角色内行动 vs 元指令（如「我要去酒馆」）vs 直接对主线 AI 下指令。
③ 多角色切换的时机（玩家主动/剧情触发）与非控制角色 AI 的运行方式（是否并行、是否可见）。
④ 失败/死亡/存档回滚语义。
⑤ 流式输出与「等待玩家确认再结算」的交互节奏。

## Answer

核心循环以「玩家输入」为回合边界，回合内固定管线：

玩家输入 → 主线 AI 生成世界回应意图（旁白/场景推进/世界变化）→ 角色 AI 生成相关角色言行意图 → 引擎统一结算（校验 + 技能/判定 + 状态回写）→ 组装输出（旁白 + 对话 + 结算结果）→ 流式呈现 → 等下一轮输入。

- AI 只产生「意图」，引擎负责结算；回合内可多轮「生成意图 → 结算」（如技能触发连锁），但边界由玩家输入划定。
- 玩家输入两层通道（UI 不猜）：**角色输入**（作为主角说话/行动/表达意图）vs **元指令**（切换主角、存档/读档、重来、调节奏、干预主线 AI）。
- 多角色：玩家随时主动切换（元指令），主线 AI 可在剧情节点建议切换；非控制可玩角色由角色 AI 继续扮演（保持世界连续），NPC 只在场景相关时响应（避免刷屏）；非控制角色言行仅在玩家可见/可闻时输出。
- 死亡 = 叙事事件（转场/换主角/读档），非硬性 game over（除非故事书或玩家设定硬核）；存档 = 手动 + 关键节点自动（快照 + 命令日志）；读档 = 从快照恢复、丢弃其后命令。
- 旁白/对话流式输出（SSE）；有代价的机制动作（技能/判定/资源消耗）在结算前暂停等玩家确认，可全局开关「免确认模式」；纯叙事动作不设确认门。
