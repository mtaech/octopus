# 存档版本迁移

Type: grilling
Status: resolved
Assignee: agent
Blocked by: 06

## Question

定义存档（及故事书模板）的版本迁移策略。需要拍板：
① 版本锚点：schema_version 放在哪一层（存档 meta / 日志头 / 快照各自标注，还是全局一处）；故事书模板版本与存档 schema 版本如何各自演进、互不阻塞。
② 模板升级路径：故事书模板升级后，基于旧模板的在档游戏怎么办——存档内嵌旧模板副本冻结，还是把存档迁移到新模板（被引用的技能/物品/人物 id 变更或消失时如何处理）。
③ 迁移机制：链式迁移函数的组织、命名与测试策略。
④ 事件溯源下的日志迁移：命令格式变更时，是重写历史日志，还是以最新快照为新原点、旧日志归档为只读。

## Answer

### ① 版本锚点：分层各记 + 故事书双版本

- 存档内部三层格式各记各的号、各涨各的（演进原因不同：库结构 = 引擎实现、命令格式 = 动作协议、快照 = 状态模型）：
  - 库结构版本：全局一处（meta 表 / SQLite `user_version`，蓝图定到「单一版本字段 + 步进迁移」这层）。
  - 日志条目、快照：各自携带 `format_version`，读取侧逐条 / 逐份识别。
- 快照格式过旧不做迁移：直接作废重建（#06 已锁快照可丢弃、任何快照可从日志重建）。
- 故事书双版本并存：`schema_version`（JSON 格式，引擎 / 编辑器发版驱动，#01 已有）+ **版次 revision**（内容版次，编辑器显式「发布」+1、玩家可见——#07 挂账的「发布版本 +1」语义在此落地）。
- 存档 meta 记录 provenance：基于哪个故事书 + 哪个版次（升级操作的依据）。

### ② 模板升级路径：内嵌冻结为默认 + 显式升级

- **默认内嵌冻结**：存档创建时把所基于的故事书完整拷贝进存档，自此冻结；存档完全自包含（#06 单文件分享 / 备份哲学的延续），作者改故事书永不破坏在档游戏。
- **显式升级**：玩家在存档管理界面手动触发（打开存档检测到新版次只提示、不自动）；永远两段式——dry-run 迁移报告 → 玩家确认 → 执行；执行前自动备份存档单文件（同目录带时间戳）。
- 升级 diff 由引擎按需计算（内嵌旧模板 vs 目标故事书均在本地），不要求作者手写变更日志。
- **编辑器纪律：实体 id 一经发布不可变**——改名 / 改描述 = 显示层修改；只有「删除 + 新增」产生新 id。升级冲突因此只剩「id 消失」一类。
- id 消失处理：
  - 技能 / 物品 / 势力 / 地点消失：默认从在档状态移除引用（角色忘掉技能、背包移除物品），逐项列入报告，玩家确认后执行。
  - **人物消失默认阻挡**：报告标红，玩家逐项选择「遗留冻结」（旧定义挪入存档遗留区，实例继续可用）或「叙事离场」（实例标记已离场 + 注入提示由主线 AI 圆叙事）；不处置完不许升级。
- 升级与命令日志的关系：升级本身**不是命令、不进日志**；存档 meta 增设「维护历史」（何时、从版次 X 到 Y、报告摘要）。升级**引起的**世界状态变更（移除引用、标记离场）作为引擎为 actor 的特殊命令进日志（可回放、可审计）。

### ③ 迁移机制：一切格式迁移 = vN → vN+1 纯函数版本链

- 库结构：SQL 步进脚本（`V2__xxx.sql` 风格 + 版本表，启动时按版本顺序执行；蓝图不锁具体 crate）。
- 升格器：每版本一个纯函数 `upcast_<artifact>_v{N}_v{N+1}(json) -> json`，读取侧按条目 `format_version` 逐段链式组合；适配器**只增不减**（不能假设玩家做过原点压缩）。
- 快照：不设升格器（太旧即作废重建，见 ①）。
- 故事书 JSON：schema_version 迁移链编辑器与引擎**共用**（引擎要读存档内嵌的旧格式模板）。
- 测试 = golden fixtures：仓库为每个历史版本留存样（旧命令日志段 / 旧故事书 JSON / 旧库文件），断言「一路升格到当前版本 = 期望结构」+「迁移后的库可正常打开重放」；每加一个版本补一个 fixture。

### ④ 日志迁移：读侧升格为主，新原点兜底

- **主线 = 读侧升格（upcast）**：日志永不改写；旧格式条目读出后经升格器升级为当前内存表示，新写入只用新格式；从零回放永远在，append-only 承诺保住。
- **兜底 = 新原点**：玩家显式触发、执行前自动备份单文件；以最新快照为存档新起点；旧日志整体挪出为单独归档文件（同目录 `<存档名>.archive-<时间戳>.sqlite`），dev 工具可只读考古；回放 / 回滚上限 = 新原点，跨原点旧分支成只读死历史；dev「任意 seq 重建」收缩为「原点之后任意 seq」。
