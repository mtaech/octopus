# 存档管理界面设计

Type: prototype
Status: resolved
Assignee: agent
Blocked by: 18

## Question

设计存档管理界面（由 #14 的维护操作浮出的前端落点）。需要拍板：
① 页面落点：**已定（#18）**——不设独立存档区，存档列表 / 详情为游玩页内抽屉（存读档菜单），列表页「继续游玩」直达最近存档；本票细化抽屉内的组织与呈现。
② 版次升级的呈现：打开存档检测到故事书新版次时的提示形态；dry-run 迁移报告如何呈现（引用变更 / 消失清单、人物消失的逐项裁决交互——遗留冻结 vs 叙事离场）；确认执行与自动备份的反馈。
③ 维护操作入口：「压缩为新原点」与维护历史（何时、X→Y、报告摘要）的展示。
④ 存档的分享 / 导入：单文件（#.sqlite）导出与导入的交互（#06 已锁单文件拷贝即分享）。
## Answer

**决议（原型 [save-manager.html](../prototypes/save-manager.html) 三变体对比 + Q1–Q7 拍板，七项全部按推荐项落定）：**

### ① 抽屉组织 = B 存读档菜单骨架 + C 升级向导形态（混合）

- **抽屉 = 游玩页内「存读档菜单」**（窄抽屉、存档卡片列 + 点开内联展开，B 形态；#18「不设独立存档区」措辞落地）。列表页「继续游玩」直达最近存档（#18 已定）。叙事主列不被挤压。
- **版次升级 = 独立聚焦视图，C 的向导形态**：从存档卡片的「升级」进入，①迁移报告 → ②确认执行（自动备份提示）→ ③执行结果 步进，面包屑返回存档列表；**不做常驻页签**（窄抽屉不承担任务栏角色），升级待办以卡片角标 + 展开面板内入口呈现。
- **维护与分享 = 展开面板内分节**（不占独立页签）：维护操作（新原点）、维护历史、分享/导入各成一节。

### ② 版次升级呈现

- **提示形态 = 打开存档（继续游玩）时游玩页一条可关闭横幅**「故事书已发布新版次 X」；抽屉内存档行角标为辅助入口。只提示、不自动（#14）。
- **dry-run 报告 = 分组折叠**（引用变更 / 人物消失两组），嵌在升级视图内，不打断「看完→裁决→确认」连贯性。
- **人物消失 = 内联单选**「遗留冻结 / 叙事离场」，逐项可见；**未裁决完禁用确认键**（#14「不处置完不许升级」的可见化）。
- **执行反馈 = 完成态**（已升级 + 备份文件名 + 维护历史落账）**+ 成功提示**，不做结果摘要屏（内容已在报告中看过）。

### ③ 维护操作

- **压缩为新原点** = 展开面板内操作卡，执行前自动备份提示；**回滚 / 分支不进 v1 抽屉 UI**（#06：v1 仅 dev 工具，玩家侧时间轴 UI 留待后续，见地图 Not yet specified）。
- **维护历史** = 表格/列表（何时、操作、报告摘要），版次升级与新原点都落账。

### ④ 分享 / 导入

- **导出** = 单文件 **.sqlite** 下载按钮（自包含，可拷贝备份 / 发送）。
- **导入** = 文件选择 + 校验（能打开即通过），进列表带「新导入」标记；**不做版次匹配检查**（存档内嵌冻结模板、自包含，#06/#14）——版本差自然在打开时触发升级提示。
