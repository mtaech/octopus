# 故事书编辑器设计

Type: prototype
Status: resolved
Assignee: agent
Blocked by: 01

## Question

设计应用内故事书编辑器的形态与体验（这是重头）。需要回答：编辑器是表单驱动、类 Notion 富编辑、还是 AI 辅助生成优先？如何组织世界/人物/技能/物品/势力/关系的编辑流？产出一个可交互的粗糙原型来对答案，原型作为资产链接在本票上。

## Assets

- 可交互原型（三范式对比：A 表单工作台 / B 文档工作台 / C AI 结对创作）：[prototypes/editor-ux.html](./prototypes/editor-ux.html)（单文件，浏览器直接打开；底栏或 ←→ 键切换变体；URL 参数 ?variant=A|B|C 可直达）

## Answer

**决议（原型 07-editor-ux.html 三范式对比 + 设计树拍板）：**

**① 主范式 = 混合**。故事书天生分两种内容——叙事（premise/人物背景/物品描述）与结构化数据（维度/消耗/判定/关系边），单一范式无法兼顾：
- **B 文档为主壳**：每个实体 = 一页文档，叙事自由书写，结构化数据用内嵌块（属性块、定义块、关系块）。
- **C AI 结对做冷启动与补全**：从设定种子起稿、生成实体卡片；采纳即落为普通实体。
- **A 表单/表格专用于纯结构化区**：关系图（有向边表）、属性维度等。

**② 骨架用独立大纲式编辑器**（不埋进文档流）：左侧场景树 + 右侧 goal/beat 卡片（触发条件/一次性/给主线 AI 的提示）。

**③ 引用双轨**：结构化字段（技能引用、势力、归属）用下拉/选择保证确定性；叙事正文用 @提及；两者落到同一引用图，实时校验面板兜底（引用完整性警告 + 被引用清单）。

**④ 属性维度独立「全局设置」区**：人物表单只消费，不内联新建；被引用维度引擎端拒绝删除。

**⑤ AI 生成不保留来源标记**：待审查 → 采纳 → 与手写实体无差别；审查期可对比/重写。

**⑥ 实时校验 + 显式「发布」**：meta.version +1；发布的具体语义（模板冻结、旧存档迁移）留给「存档版本迁移」票，本票只锁「发布」概念存在。

**反馈修订（用户）**：A 与 C 为主范式，各有明确角色——**A 表单工作台 = 有计划的详细编辑**（目标明确、逐项精修时用）；**C AI 结对 = 没有头绪时的启发式编辑**（冷启动/探索、边聊边成型）。B 文档主壳保留为叙事自由书写的载体，不再是「主壳」，定位随 A/C 调整。

**待办交圈**：编辑器后端需提供故事书 CRUD + 引用校验 + 发布接口，随引擎设计蓝图落定。

## 修订（设计复审 2026-09-09）

- 发布语义 = **版次 revision**（#14/#23）；原「meta.version +1」作废。
- 叙事字段编辑 / 存储格式 = **Markdown**。
- 新增 `objects` 编辑与声明区（flags/events/relationship_types/target_types）编辑。
