# 列表页设计（故事书 / 存档入口）

Type: prototype
Status: resolved
Assignee: agent
Blocked by:

## Question

设计列表页（`/` 路由，#18 已定「故事书列表（含继续游玩最近存档直达）」）的 UI 规格——故事书与存档的入口页。数据源已随「游玩页后端 API 设计」落定（#23/#24）：

- 故事书列表：`GET /api/storybooks?released=1` → `{ id, title, revision, released_at? }`（服务端过滤已发布；编辑侧入口另由编辑器路由承担）
- 存档列表：`GET /api/saves` → `[{ id, storybook_id, storybook_title, embedded_revision, latest_revision, needs_upgrade, created_at, updated_at, last_played_at }]`，按 `last_played_at` 降序
- 「继续游玩」直达最近存档（#18/#21 已定）
- 新建游戏 = 基于已发布故事书开档 `POST /api/saves { storybook_id }`
- 导入入口 = `POST /api/saves/import`（#21 已定交互：文件选择 + 能打开即通过 + 「新导入」标记）

需要拍板：

① 页面组织：故事书与存档两列表如何共处一页——分区并置？卡片流混合？「继续游玩」「新建游戏」「导入」三个入口的层级、位置与默认态（无存档时入口如何呈现）。

② 卡片内容与操作：故事书卡（标题 / 版次 / 发布态 / 操作：新建游戏、进编辑器）与存档卡（标题 / 故事书名 / 时间 / 需升级角标 / 操作：继续游玩、升级入口）各自展示哪些字段、哪些操作常驻 vs 折叠。

③ 空态与引导：无故事书 / 无存档时的引导路径（去编辑器新建？去故事书开档？）。

④ 与游玩页抽屉的关系：存档管理（#21 抽屉）是否从列表页可触达，还是列表页只做入口直达（继续游玩 / 新建 / 导入），管理操作全部进游玩页抽屉。

⑤ 进入流程：列表页 → 新建游戏 → 直接进游玩页（`/play/:saveId`）还是先经确认/取名；「继续游玩」对最近存档的直达是否带「需升级」中间态（#21 横幅逻辑在游玩页，列表直达是否先行提示）。


## Answer

**决议（原型 [list-page.html](../prototypes/list-page.html) 三变体对比 + Q1–Q5 拍板，全部按推荐项落定）：**

### ① 页面组织 = A 分区并置

- 顶部**动作带**（「继续游玩」大卡 + 新建游戏 + 导入）→ **故事书网格** → **存档列表**，自上而下三区；「最近存档」区按 last_played_at 降序，天然兼顾时效（B 的诉求）。入口页核心动作 = 继续游玩 + 基于某故事书开档，分区并置让两类实体各归其位。B（卡片流混合）/ C（侧栏分栏）保留作对比。

### ② 卡片内容与操作

- **故事书卡** = 标题 / 版次 / 发布态 + 常驻操作：新建游戏 · 进编辑器。
- **存档卡** = 标题 / 故事书名 / 版次 / 时间 / 需升级角标 + 常驻操作：继续游玩；「升级」仅在 needs_upgrade 时出现；「新导入」标记随导入存档显示（#21）。
- **管理操作（升级向导 / 新原点 / 分享）全部不进列表卡**——列表卡只做「打开一件事」，维护动作留在游玩页抽屉（#21），避免同一操作两处入口。

### ③ 空态与引导

- **无故事书** = 全页空态，唯一出路引导「去编辑器新建」。
- **无存档但故事书在** = 故事书列表仍是主体，存档区局部空态引导「新建游戏 / 导入」。

### ④ 与游玩页抽屉的关系 = 列表页只做入口直达

- 列表页 = 继续游玩 / 新建游戏 / 导入 三个入口动作；**存档管理（升级 / 新原点 / 分享）全部留在游玩页抽屉**（#21 已把管理 UI 定死其中），列表页不留「管理」深链入口，避免同一操作两处。#21 的「导入」本身是入口动作，留在列表。

### ⑤ 进入流程

- **新建游戏 = 先确认再开档**：选故事书 + 起名（可默认书名一键确认）→ 开档 → 进游玩页（开档是不可逆写操作，确认成本极低、防误触）。
- **「继续游玩」对需升级存档 = 直达**：#21 已定升级「只提示、不自动」，提示横幅在游玩页出现即可；列表页不出中间态、不打断直达心智。

### 解锁 / 新增

- 无新开票；本票为最后一个前沿票，关票后**地图前沿清空、抵达地图终点**（v1 技术设计蓝图各票齐备），交给开工。
