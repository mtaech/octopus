# 一致性/防幻觉约束机制

Type: grilling
Status: resolved
Assignee: agent
Blocked by: 04, 05

## Question

定义 AI 叙事的一致性约束与防幻觉机制。需要拍板：
① 硬约束（引擎端强制）：哪些事实 AI 无权捏造（角色属性值、技能存在性、物品归属、关系状态）——引擎在 validate 阶段如何拦截冲突。
② 软约束（prompt 引导）：如何在系统 prompt 中注入一致性规则（如「角色 A 已死亡，不得让其说话」）。
③ 冲突检测：AI 产出的叙事与已记录事实冲突时，是自动修正、提示玩家裁决、还是允许 AI 覆盖（如「其实那个 NPC 是伪装的」）。
④ 上下文窗口的「遗忘」问题：当相关事件超出检索窗口，AI 可能产生矛盾叙事——如何设计兜底（如关键事实清单、不可变事实标记）。
⑤ 角色 AI 的认知边界：角色 AI 可以「记错」或「不知道」——如何区分「有意的角色认知限制」与「真正的 AI 幻觉」。
## Answer

**总原则：故事推进优先，幻觉治理不建机检机制。** 幻觉是模型 + prompt 的问题，随两者迭代；单条幻觉由玩家自行纠正。

- **① 硬约束**：不加叙事校验器 / 软门自证 / 冲突裁决卡。机制事实由 #04 校验管线结构性兜底——`speak`/`narrate`/`emote` 之外的意图全过六种驳回码校验，机制事实无法被叙事「说成真」（无结算不生效）。
- **② 软约束**：仅 prompt 工程——系统 prompt 模板加一致性条款（不得与注入的事实矛盾）。注入事实 = #05 分层注入（已含当前状态渲染）；故事书世界设定自由文本天然承载世界规则，不设专门规则区。
- **③ 冲突处理**：玩家自纠三路径，全部现成——`intervene` 元指令（#04）、回滚即分支（#06）、要求重述。引擎不做任何冲突检测。
- **④ 遗忘**：依赖 #05 双层摘要 + top 5 检索；置顶事实清单 v1 不做，实测窗口外矛盾频发再立项（已挂地图 Not yet specified）。
- **⑤ 角色 AI 认知边界**：机制已由 #04 查询范围限制 + #05 上下文隔离保证；prompt 条款一句——「对你在场见证的事实不得矛盾；此外可自由无知、猜测、记错」。不做认知状态建模。
