# 运行时状态与持久化

Type: grilling
Status: resolved
Blocked by: 01

## Question

定义运行时世界状态与持久化策略。需要拍板：
① 运行时状态模型（世界/角色/任务/物品栏/关系状态的结构）。
② 命令日志（事件流）的 schema 与权威性。
③ 快照的时机与格式。
④ 存储选型（SQLite vs Postgres vs 文件）及理由。
⑤ 回放/回滚能力边界。
⑥ 为多人预留的架构落点（服务端权威 + 命令模式的程度）。

## Answer

① **运行时状态模型**：扁平分面 + id 互引。角色实例 = `{ instance_id, template_id, 当前属性覆盖, 位置, 状态效果[] }`；物品栏 / 关系 / 任务进度 / 世界旗标各自成面。叙事产物（滚动摘要、记忆检索索引、对话历史）**非权威**，单独命名空间存储、可重建——权威状态只含世界事实。
② **命令日志 = 唯一权威**（严格事件溯源），记**命令**不记意图。条目 = `{ seq, branch_id, turn_id, actor, command_type, payload, rng 消耗记录(种子+序号+结果), 状态 diff, 叙事结果摘要 }`。被驳回的非法意图只进 debug 流，不进权威日志。（对「规则系统设计」票的约束：一切随机性必须走引擎种子 RNG 并记录消耗，否则不可回放。）
③ **快照**：全量物化状态 JSON，`{ seq, taken_at, state_json }` 存同一库文件。时机 = 每 ~100 条命令（可配）+ 场景切换 + 干净退出 + 手动存档。保留最近 5 份。快照只是启动加速缓存（启动 = 最新快照 + 重放其后命令），丢失可从零重放重建；日志永不删。
④ **存储 = SQLite，一个存档 = 一个 .sqlite 文件**（WAL 模式）。备份/分享/删除 = 拷贝单文件；FTS5 预留给「上下文与记忆管线」的关键词检索。故事书模板是独立文件（编辑器侧）。一个故事书可实例化 N 个存档。
⑤ **回放/回滚**：日志 append-only。回滚 = **分支**：从 seq N 重放出状态，后续命令写新 `branch_id`，旧分支原样保留。只读回放：任意 seq 的世界状态可经「最近快照 + 重放」重建，v1 先暴露给 dev 调试；玩家侧时间轴 UI 归「游玩界面设计」票。
⑥ **多人预留**：Player 作为一等实体现在进模型——`{ player_id, controlled_instances[] }`，命令 `actor` 字段区分行为者。不建房间/会话/网络同步抽象（出 scope，另起地图）。纪律 = 一切状态变更走命令管线 + 服务端权威，已在 ② 锁死。
